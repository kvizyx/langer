# langer_mediapipe

[MediaPipe's language detector](https://ai.google.dev/edge/mediapipe/solutions/text/language_detector)
in pure Rust: no TFLite runtime, no C++, the ~300 KiB model embedded in the library. It returns
the same predictions as MediaPipe (see [Parity](#parity)).

```rust
let detector = langer_mediapipe::Detector::new()?;
let top = detector.predict("Привет, как дела?", 1)?;
assert_eq!(top[0].language, "ru");
```

Loading checks the whole model, and prediction never panics: both return errors instead,
including for models other than the bundled one.

## How it works

The crate reads the `.tflite` file with flatbuffer bindings generated by `flatc`, checks that its
graph is exactly the one it implements, and reimplements the model's operators:

- `NGramHash` (MediaPipe custom op): tokenization and lowercasing with the Plan 9 Unicode tables,
  character n-grams hashed with MediaPipe's MurmurHash64 variant;
- `KmeansEmbeddingLookup` (MediaPipe custom op);
- the fully connected layers as TFLite's XNNPACK delegate runs them: dynamic asymmetric `i8`
  input quantization, rescaling with fused multiply-add;
- softmax.

The labels come from `labels.txt` in the zip archive appended to the model.

| module | contents |
|---|---|
| `src/model.rs` | model loading, graph validation, `Detector` |
| `src/ngram.rs`, `src/murmur.rs`, `src/unicode.rs` | `NGramHash` |
| `src/layers.rs` | embeddings, fully connected layers, softmax |
| `src/schema_generated.rs` | `flatc` output for the TFLite schema; do not edit |
| `build.rs` | compiles the character tables from the vendored C header |

## Vendored files

Third-party files in `vendor/` are managed with [vendir](https://carvel.dev/vendir/):
[`vendir.yml`](vendir.yml) pins every file to an exact upstream URL and sha256, and vendir refuses
a download whose hash differs. [`vendir.lock.yml`](vendir.lock.yml) is written by vendir; commit
it with the config. The files are kept unmodified and licensed under the Apache License 2.0
([`vendor/license/LICENSE-2.0.txt`](vendor/license/LICENSE-2.0.txt)).

| file | pinned to | used by |
|---|---|---|
| `vendor/model/language_detector.tflite` | `float32/1` on Google's model storage | `include_bytes!` in `src/model.rs` |
| `vendor/mediapipe/runetypebody.h` | MediaPipe commit `998a5d77` | `build.rs` |
| `vendor/tflite/schema.fbs` | TensorFlow commit `048b2af2` | source of `src/schema_generated.rs` |
| `vendor/license/LICENSE-2.0.txt` | apache.org | — |

- **The model** is the only version Google has published (`float32/latest` serves the same file).
  It is also a zip archive, so `vendir.yml` disables unpacking for it.
- **The character tables** must match the ones the model was built with, not current Unicode;
  upstream has not changed them since 2023. `build.rs` parses the header's arrays into Rust
  constants at build time and checks their shape and order.
- **The schema** only ever gains fields and operators (old models must keep loading), so this model
  reads the same with any newer version; it only needs updating to support new operators. The
  bindings are generated with `flatc` 25.12.19, the version of the `flatbuffers` crate.

Building and testing need no vendir; only updating vendored files does.

### Updating

1. Change the file's `url` and `sha256` in `vendir.yml`.
2. Run vendir 0.46 or newer in this directory; it replaces `vendor/` with exactly the configured
   files:

   ```bash
   vendir sync
   ```

3. For the schema, regenerate the bindings with the `flatc` matching the `flatbuffers` crate:

   ```bash
   flatc --rust -o src vendor/tflite/schema.fbs
   ```

4. Run the tests and the parity test; any change to the model or the character tables must keep
   it passing.

### Checking

To check that `vendor/` matches `vendir.yml` (e.g. in CI), sync and look for changes:

```bash
vendir sync && git diff --exit-code vendor/
```

## Parity

Compared with MediaPipe 1.1.1 on 97 439 texts (Lingua's test data,
papluca/language-identification, and edge cases: emoji, digits, long and mixed-script texts,
random Unicode), the top language matches for every text, with probabilities within 1e-5 for
all but 6. Those 6 contain characters whose lowercase form is shorter in UTF-8 (two or more
Turkish `İ`, for example): MediaPipe then tokenizes past the end of its lowercased buffer and
reads uninitialized memory, which cannot be reproduced. Their top language still matches.
